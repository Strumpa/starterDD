# Test data policy

The repository must stay light. Large results (DRAGON COMPOs, Serpent2 outputs)
are **never committed**. Tests use three tiers of data:

| Tier | What | Where | In git | When it runs |
|---|---|---|---|---|
| 1 | Synthetic DRAGON/Serpent2 files generated by the tests | in memory / `tmp_path` | — (code only) | always |
| 2 | Small **real** GE14 subset (~0.6 MB) | `tests/data/ge14_mini/` | yes | always |
| 3 | Full local data | `$STARTERDD_TEST_DATA` (default `temp_examples/`), `$DONJON_DATA_DIR` (default `../../../5.1/Donjon/data`) | **no** | when present; tests are marked `fulldata` and skipped otherwise |

Run without tier 3: `pytest -m "not fulldata"`.

## Tier 2: `ge14_mini`

The data is extracted from the GE14 DOM 1L run at 0 % void
(`coolant_density_1L_PT_3x3_HFP/.../2026-07-19T10-46-27`) and its Serpent2
reference, by [`ge14_mini/build_fixture.py`](ge14_mini/build_fixture.py). The
script also verifies that the subset reads back identically to the source.
`SOURCES.json` records the SHA-256 of every source file.

| File | Content |
|---|---|
| `_CPO_GE14_DOM_DIAG_mini.gz` | COMPO top-level entries `SIGNATURE`, `EDIHOM_COND`, `EDIR_2G` (51 pins, 2 groups), copied verbatim |
| `GE14_DOM_00_endfb8r1.serp.gz` | Legacy Serpent2 input, unmodified (non-standard detector names) |
| `GE14_DOM_00_endfb8r1.serp_res.m.gz` | Serpent2 results, unmodified |
| `GE14_DOM_00_endfb8r1.serp_det0.m.gz` | Detectors of pins 1, 2, 15, 28 (UOX on/off diagonal, Gd on/off diagonal), plus `det_assembly_295g` and `flux_295g`, all at 295 groups |
| `GE14_DOM_00_endfb8r1.serp.detectors.json` | Frozen detector manifest restricted to those detectors |
| `golden/` | Outputs of the original analysis scripts: `2G_data.npz`, `density_00_*.txt`, the 0 % rows of `sortie_DOM_1L_PT_3x3_HFP.csv`, the DRAGON `run_manifest.yaml`, and `reference_values.json` (keff 0.989089489 vs 0.990261, −117.15 pcm) |

The geometry and compositions of this case are regular inputs under
`data/BWRProgressionProblems/GE14_inputs/ASSEMBLY/` (`GEOM_GE14_DOM_DIAG.yaml`,
`material_compos_{00,40,80}.yaml`, public benchmark isotopics).

`2G_data.npz` stores per-pin rates **before** normalisation. Its columns for
the four fixture pins can therefore be rebuilt exactly from tier 2. Quantities
that need all 51 pins (total power, normalised maps) are tested in tier 3.

To rebuild or extend the fixture (for example with more pins), run this from
the repository root with the full data present:

```bash
python tests/data/ge14_mini/build_fixture.py --pins 1 2 15 28
```

Keep the total under about 1 MB. A per-pin 295-group Serpent detector costs
about 55 KB gzipped, because Monte Carlo noise does not compress.
